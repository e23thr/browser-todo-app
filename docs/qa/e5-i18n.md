## 1. Catalog parity — every en key has a th value (AC confirmation)

`npm run i18n:check` → **PASS** (`i18n-logs/i18n-check.txt`):

- **190 keys in `en.json` / 190 keys in `th.json`; the key sets are identical and every
  `{placeholder}` set is identical.** The gate also rejects non-string and *empty* values, so
  "every en key has a th value" is enforced mechanically, not just observed.
- 71 distinct keys are consumed by 77 literal `t('…')` call sites; every one resolves against
  `en.json`. 2 call sites use a non-literal key (`app/Shell.tsx:173`, `:246` — the nav
  `labelKey` indirection) and are listed as informational by the gate; both were spot-checked
  by hand (`nav.*` keys all exist in both catalogs).

**The gate was independently proven to FAIL, not just pass** (`gate-failure-proofs.txt`): 8
fixture runs, each exiting 1 with the expected violation class —
`missing-in-th`, `extra-in-th`, `placeholder-mismatch`, `empty-value`, `malformed-key`,
`duplicate-key` (raw-text duplicate that `JSON.parse` would silently collapse), and
`unknown-key` (a key used in `src/` but missing from `en.json`). Baseline fixture exits 0.

## 3. Per-locale lazy load — locale bundles are NOT in the initial payload

Verified three independent ways:

1. **Bundle manifest** (`dist/.vite/manifest.json`, clean build): `src/i18n/locale-en.ts` and
   `src/i18n/locale-th.ts` are `isDynamicEntry: true`, reachable only through the entry's
   `dynamicImports` — the static import closure of `index.html` contains no locale catalog.
2. **Budget gate**: `locales-lazy = 0 hit(s) — no locale pack is inside the initial JS closure` (PASS).
3. **Runtime network trace** (browser, clean build): on boot the page fetches
   `index-*.js`, `index-*.css`, `favicon.svg`, `locale-en-*.js` only. The Thai pack
   `locale-th-C-9mtQcD.js` appears in `performance` resource timing **only after the user
   switches to Thai**. (English is fetched at boot by design — it is the fallback catalog,
   see `src/i18n/index.ts` module contract.)

A raw-text scan of the fetched chunks confirms no Thai catalog values ship in the initial
JS closure (Thai text found only in the `locale-*` chunks and the `settings.language.thai`
endonym — see §8 note).

### 4.3 Durability across reload (ADR-002 `settings.locale`, boot contract)

| Check | Actual |
|---|---|
| After switch to Thai, raw IDB row `settings.locale` | `th` (verified by direct IndexedDB read) |
| After `location.reload()` | **PASS** — `lang=th` restored, radio `th` checked, `h1=การตั้งค่า`, row still `th` (verified twice on the clean-HEAD build; also true for the `en` round trip) |
| Regression drills | `tests/unit/i18n-reload-qa.test.ts` — 3 green: two-simulated-session restore, persistence-port read-back, and a wrapper-vs-raw read check (the denylist-mismatch detector) |

**Cross-card incident (resolved, not an i18n defect):** while this QA ran, a build made from the
shared working tree *before* storage commit `bb347b5` ("fix(storage): Tx.get denylist, …")
reproducibly reset the locale to English on every reload (3× live reproduction). Mechanism
observed with IDB instrumentation: the `settings` row existed on disk (raw read OK) but the
storage wrapper's `get('settings', …)` returned `ok(undefined)`; `initLocale()`'s `load()`
therefore silently saw "no stored locale", booted English, and the boot-time `save('en')`
clobbered the stored `th`. That is exactly the wrapper-read/denylist fault fixed in `bb347b5`;
at HEAD `bf74495` the behavior is correct. The i18n runtime itself was unchanged throughout.
The drills above now pin this behavior. (Soft-spot worth knowing: `LocalePersistence.load()`
returns `null` *silently* when the wrapper reports `!ok`/`undefined` — a future regression of
this class would again look like "the app forgot my language" with zero console output. A
`console.warn` on the `!row.ok` branch would make it observable; non-blocking suggestion.)

## 9. Thai text accessibility (§8 / design §9)

### 9.1 Line-height & diacritic stacking

Computed values (measured at 200 % text zoom, Thai locale): view title 81 px/60 px = **1.35**,
section caption 39/26 = **1.5**, body-sm 43.4/28 = **1.55**, wordmark 1.45. Tokens
(`src/styles/tokens.css`) match the design scale exactly: display/title 1.35, h2 1.4, h3 1.45,
body 1.6, body-sm 1.55, caption 1.5 — **every value ≥ the 1.35 floor** (design §9.2).
`letter-spacing: 0` and `overflow-wrap: break-word; word-break: break-word` are set globally
(`global.css`), per §9.3. Line-clamp reservations (§9.2 task titles) cannot be exercised yet —
task rows belong to the core-UI/M1 card; verify there.

### 9.2 200 %-zoom & reflow (design §9.5 QA gates)

| Gate | Measurement | Visual (4 screenshots in `e5-i18n-logs/`) | Verdict |
|---|---|---|---|
| (a) text-size 200 % (root 32 px) @1280 px viewport | `scrollWidth` 1265 ≤ 1280 — no horizontal scroll | tone marks/upper vowels stack cleanly (e.g. `ข้าง`, `พื้น`, `การตั้งค่า`), no clipping into neighbouring lines, no overlap, no tofu | PASS |
| (b) 320 px viewport, normal text | `scrollWidth` 320 = 320; mobile layout active (appbar + tab bar + FAB) | all strings fit, radio groups wrap, tab bar + FAB render | PASS |
| (c) 320 px + 200 % text | `scrollWidth` 320 = 320 | diacritics clean, controls visible and operable, only vertical viewport cropping | PASS |

Below 360 px the tab labels hide via the sr-only clip pattern
(`shell.css` `@media (max-width: 359px)`: `position:absolute; 1×1; clip-path: inset(50%)`) —
the label **text stays in the accessibility tree**, so icons keep accessible names. This is
the *only* allowed label-hiding case, exactly as design §9.5 specifies.

### 9.3 Screen-reader language switching

- Mechanism verified: `document.documentElement.lang` tracks the locale (`en` → `th` → `en`,
  persists across reload), which is what NVDA/VoiceOver key pronunciation off; the language
  change is announced through the polite live region (§4.1).
- **Manual SR pass NOT TESTABLE in this environment**: the QA host is headless Linux without
  NVDA or VoiceOver, and Thai TTS voice availability is the known QA constraint called out in
  §8 itself. The NVDA/VoiceOver per-locale manual pass remains owed by the M13 release-gate
  card (t_b788bacf) and must be run on Windows/macOS per §8 "Testing". Recorded here as
  not-tested, per the card's instruction to state what was and wasn't testable.
